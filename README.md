# bitget-ai-bot

비트겟 USDT-M 무기한 선물용 개인 자동매매 봇과 그 주변 도구(원클릭 컨트롤 패널, 폰 PWA, 거래별 사후 분석, 연구 스파이크).
한 사람(개발자 본인)의 소액 계정에서 돌리는 것이 목적이고, 다른 사람이 쓰도록 만든 제품이 아닙니다.

> **면책**: 가상자산 선물 거래는 원금 전부를 잃을 수 있습니다. 이 저장소의 코드·백테스트·연구 결과는 투자 권유가 아니며, 그대로 돌려서 손실이 나도 책임지지 않습니다. 레퍼럴 링크는 만들지도 쓰지도 않습니다.

## 이 프로젝트가 답하려던 질문

1. 소액·저배율·규칙 기반 봇을 **버그나 재시작 때문에 손절 없이 포지션이 방치되는 일 없이** 24/7 돌릴 수 있는가?
2. 지표·거시 이벤트·포지션 데이터·실제 거래 결과로 학습한 모델이 **표본 외에서 진입 승패를 가를 수 있는가?**

2번의 답은 **"아니오"** 였습니다. 네 차례 연구(아래) 모두 표본 외 판별력(AUC)이 0.47~0.53으로 동전 던지기와 같았고, 미리 정한 합격 기준을 통과한 모델은 0개였습니다. 그래서 실전은 모델 없이 규칙만 쓰고, 봇이 하는 일의 대부분은 **잃지 않게 막는 장치**입니다.

## 구조

```
freqtrade/            Freqtrade 엔진 설정, SafeTrendLive 전략, 거시 일정(FOMC/CPI/PPI/고용) CSV
bitgetbot/
  panel/              원클릭 컨트롤 패널 (FastAPI + PWA). 모드 전환, 자동매매 켜기/끄기, 포지션 카드,
                      시장가 청산, 익절 목표, 비상 정지, 사후 분석 리포트 목록
  postmortem/         거래가 끝날 때마다 시장 데이터 + 뉴스 조사(claude -p) → 리포트 json/md
  smoke.py            최소 실전 주문 → 거래소 손절 확인 → 재시작 → 청산 → 장부 CSV 스모크 경로
  privcfg.py          비밀값 분리 (config.private.json, 커밋 금지)
launcher/             Windows 바탕화면 원클릭 실행 (PowerShell)
docs/superpowers/     설계서(spec)와 계획(plan). 결정마다 [사용자]/[Claude] 꼬리표로 누가 정했는지 기록
docs/runbooks/        스모크 테스트, 패널, 실전 전환, 사후 분석 운영 절차
docs/examples/        사후 분석 리포트 샘플
tests/                pytest 1,091개 (가짜 거래소·가짜 Freqtrade만 사용, 네트워크 없음)
```

- 엔진은 Freqtrade. 전략·주문·거래소 손절은 Freqtrade가, 안전선·패널·분석은 `bitgetbot/`이 맡습니다.
- 패널은 `127.0.0.1`과 Tailscale tailnet(`*.ts.net`)에서만 응답합니다. 공인 인터넷에 노출되지 않습니다(Funnel 금지).
- 위젯용 읽기 전용 토큰은 `GET /api/widget/summary` 하나만 열며, 주문 API를 부를 수 없습니다. 데스크톱 위젯은 [robo-briefing](https://github.com/ddaokki/robo-briefing)의 `trading` 카드입니다.

## 실전 규칙 (SafeTrendLive, 2026-10-21 이후)

| 항목 | 값 |
|---|---|
| 대상 | BTC 롱만, 포지션 1개 |
| 크기 | 레버리지 2배, 거래당 위험 0.5% |
| 진입 차단 | 하루 3회, 오늘 -3% 또는 이번 주 -6% 실현 손실이면 정지 |
| 보호 장치 | 청산 뒤 4시간 대기, 24시간에 손절 2번이면 24시간 정지, 30일 낙폭 10%면 7일 정지 |
| 블랙아웃 | FOMC·CPI·PPI·고용 발표 ±2시간 새 진입 금지 (연준·BLS 공식 일정, 2027년 말까지) |
| 청산 | 샹들리에(3×ATR) 추적 손절. 손절선이 현재가 위면 즉시 시장가 청산 |

- 3년 in-sample 백테스트(2023-10~2026-10, 지갑 105 USDT): 65건, +9.9%, PF 1.86, 최대 낙폭 2.1%.
- 규칙을 고를 때 보지 않은 2020-01~2023-09 홀드아웃: 59건, +8.1%, PF 1.69, 최대 낙폭 2.5%. 하락장 2022년 진입 0건.
- 같은 기간 BTC를 그냥 들고 있었으면 +204% / +275%입니다. 이 봇은 수익을 노리는 것이 아니라 **잃지 않으면서 자동매매 운영을 배우는 것**이 목적입니다.
- 실전 전환(모드 전환 + `LIVE` 입력)은 사람만 합니다. 코드도 Claude도 실전을 켜지 않습니다.

## 연구 스파이크 (브랜치 `spike/90d-backtest`, `research/`)

결과를 보기 전에 합격 기준을 고정하고, 검증자 리뷰 지적(1차 8건, 2차 6건)을 반영해 다시 돌린 기록입니다. 모든 숫자는 수수료 0.06% + 펀딩 보수 가정 포함, 낙폭은 1시간마다 평가손익 기준입니다.

| 차수 | 질문 | 결과 |
|---|---|---|
| 1·2차 `2026-10-20-90d-backtest` | 지표 + 거시 이벤트로 학습한 FreqAI 필터·확신도 등급이 기준 전략을 이기나? | AUC 0.51~0.52. 보정된 p가 0.45를 거의 넘지 않아 "확실한 자리"를 구분하지 못함. 승격 없음 |
| 3차 `2026-10-21-derivs` | 펀딩·미결제약정·롱숏 비율(바이낸스 공개 데이터) 18개 특징 + 코인 10개 통합 모델이면? | 신호 자리 AUC 0.45~0.53. 포지션 특징은 모델이 많이 썼지만 승패를 가르지 못함. 달력 24개만 고쳐도 수익이 7~10%p 흔들림 |
| 4차 `2026-10-21-metalabel` | 라벨이 틀렸나? 실제 거래 결과(R 배수)로 직접 배우면(메타 라벨) 되나? | 라벨은 멀쩡함(실제 R과 스피어만 0.71). 문제는 **재료가 다음 분기 승패를 모름**: 시기별 승률 21~54%, 지속성 0, 상위 10% 거래가 이익의 67%. 합격 모델 0/8, 고정 규칙 0/5 |
| 홀드아웃 `2026-10-21-holdout` | 실전 규칙을 안 본 기간(2020~2023-09)에 그대로 돌리면? | 방향·크기 유지(위 표). 크기를 키울 근거는 없음 |
| 청산 변형 `2026-10-23-exit-variants` | 본전 이동·부분 익절·2.5×ATR 추적이 더 낫나? | 두 기간 모두 나은 변형 없음. 차이 1~2 USDT, t값 2 미만 |

4차 README에는 "이 폴더는 결과가 나올 때까지 커밋되지 않았으므로 사전 등록을 밖에서 검증할 수 없다"는 한계도 그대로 적어 두었습니다.

## 거래별 사후 분석

거래가 닫힐 때마다 패널의 감시 스레드가 (1) 비트겟 공개 1시간봉으로 보유 중 고저·변동성·급변 여부를 계산하고, (2) `claude -p --safe-mode`로 그 시간대의 거시·지정학 사건을 웹 검색해 **검색 결과에 실제로 있던 URL만** 출처로 인정하며, (3) 원인을 규칙/사건/운 중 하나로 판정해 `reports/postmortem/`에 json·md로 남깁니다. 비밀값·계정 식별자는 프롬프트에 들어가지 않습니다(화이트리스트 필드만 전달, 테스트로 강제). 샘플: [`docs/examples/postmortem-sample-live-2.md`](docs/examples/postmortem-sample-live-2.md).

## 실행

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python -m pytest -q          # 네트워크 없이 전부 돕니다
```

실전·모의 실행 절차는 `docs/runbooks/smoke-test.md` → `panel.md` → `live.md` 순서입니다. 비밀값은 `freqtrade/user_data/config.private.json`(예시: `config.private.example.json`)에만 두고, 그 파일은 커밋되지 않습니다.

## 만든 방법

설계서를 먼저 쓰고(`docs/superpowers/specs/`), 계획 문서를 작업 단위로 나눠(`docs/superpowers/plans/`) Claude Code 세션 여러 개가 각자 worktree에서 구현했습니다. 결정마다 **[사용자]**(내가 정함) / **[Claude]**(제안을 내가 승인) 꼬리표가 붙어 있어, 어떤 판단이 누구 것인지 설계서에서 추적할 수 있습니다. 코드 리뷰와 연구 결과 검증도 별도 세션이 맡아 지적 사항을 문서에 남겼습니다.
