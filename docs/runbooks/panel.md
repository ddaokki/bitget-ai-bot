# 비트겟 봇 제어판 사용 안내

## 1. 바로가기 설치: 처음 한 번

이 PC에 Docker Desktop과 저장소의 Python 가상환경(`.venv`)이 준비되어 있어야 합니다.
저장소를 옮기면 바로가기를 다시 설치하세요.

PowerShell에서 저장소 폴더로 이동한 뒤 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File launcher\install-shortcut.ps1
```

바탕화면에 **비트겟 봇** 바로가기가 생깁니다. 이후에는 바로가기를 두 번 클릭하세요.
Docker Desktop 준비, 거래 봇 시작, 패널 실행, Edge 앱 창 열기를 처리합니다.
Docker 준비는 최대 120초, 거래 봇 시작 명령은 최대 120초, 패널 준비는 최대 20초 기다립니다.
Edge가 없으면 기본 브라우저로 엽니다. 이미 실행 중인 패널은 Docker 확인보다 **먼저** 창을 엽니다.
Docker나 거래 봇 시작이 실패해도 패널은 시작해서 열고, 화면에 도커 상태를 표시합니다.
오류 창은 패널 자체를 시작하거나 열 수 없을 때만 뜹니다. 급하면 비트겟 웹(PC)에서 직접 청산하세요.
로그인 토큰을 복사하거나 공유하지 마세요. 주소를 직접 입력하는 대신 바로가기로 여세요.

**바로가기는 저장된 거래 모드를 바꾸지 않습니다.** 모의 거래인지 실전 거래인지 화면에서 반드시 확인하세요.
창을 닫아도 패널과 거래 봇은 계속 실행됩니다. 창 닫기는 청산이나 봇 중지가 아닙니다.

## 2. 데스크톱에서 단계별 사용

1. 상단의 **모의 거래 / 실전 거래**, 도커, 거래 봇 상태를 확인합니다.
   연결이 끊겼거나 모드를 확인할 수 없으면 진입하지 마세요.
2. 처음에는 **모의 거래**에서 검증하세요. 필요하면 **모의로 전환**을 누르고 거래 봇 상태가 모의로 바뀌었는지 확인합니다.
3. **사전 점검**을 누르고 진행 기록에서 성공을 확인합니다.
4. **진입**을 누릅니다. 실전 진입은 확인 창에 대문자 `LIVE`를 정확히 입력한 뒤 **확인 후 실행**을 눌러야 합니다.
5. **손절 확인**을 누르고 결과를 확인합니다. 모의 모드는 거래소 손절 주문을 조회하지 않습니다.
6. **재시작 확인**을 누르고 결과를 확인합니다.
7. **청산**을 누르고 확인 창에서 실행합니다. 접수 메시지만 믿지 말고 포지션과 체결 결과를 확인하세요.
8. 실전 거래의 청산 확인이 끝났으면 **장부 저장**을 누릅니다. 모의 거래에서는 이 버튼을 사용하지 않습니다.

각 단계가 완료된 뒤 다음 버튼을 누르세요. 작업 중에는 다른 단계와 모드 전환이 잠깁니다.
새로고침, 화면 전환, 모드 변경 후에는 진입 전 사전 점검을 다시 해야 할 수 있습니다.
진행 상태가 남아 있으면 새 진입 대신 기존 거래의 확인·청산 단계를 진행합니다.

### 자동매매 (계획 2)

거래 봇은 전략 `SafeTrendLive`(BTC 롱 전용)를 실행합니다. 모드 전환이나 재시작 뒤에는 **새 진입 멈춤**(paused) 상태로 켜집니다. 이 상태에서도 열린 포지션과 손절은 계속 관리하고, 긴급 청산도 됩니다. 새 진입은 **자동매매 켜기**를 눌러야 시작합니다.
- **자동매매 켜기**: 전략이 스스로 진입·청산을 시작합니다. 실전 모드에서는 `LIVE` 입력이 필요합니다.
- **자동매매 멈추기**: 새 진입만 멈춥니다. 열린 포지션과 손절은 계속 관리합니다.
규칙, 위험, 실전 켜는 순서는 [live.md](live.md)를 보세요.

**실전으로 전환**도 `LIVE` 확인이 필요합니다. 실제 자금이 사용되며, 모드 변경은 기존 포지션을 청산하지 않습니다.
진행 중인 스모크 거래(진행 상태 파일)가 있거나 거래 봇이 열린 거래를 보고하면 모드 전환이 거부됩니다.
이때는 **진행 중인 거래를 먼저 청산하세요**. 모드를 바꾸면 다른 모드의 포지션이 화면과 긴급 청산에서 사라지기 때문입니다.
거래소 API 키가 필요하면 PC의 **설정 · 이 PC에서만 표시 → 거래소 API 키**에서 저장합니다.
작업 중에는 키를 저장할 수 없습니다. 키 저장 후 **거래 봇을 재시작해야 새 키가 적용됩니다.**
키, 시크릿, 패스프레이즈, PIN, 토큰이 담긴 파일이나 화면을 공유하지 마세요.

### 긴급 청산

하단 **봇 거래 청산 준비**를 누른 뒤 **3초 안에 눌러 봇 거래 청산**을 누릅니다.
이 버튼은 거래 봇(Freqtrade)이 연 거래를 시장가로 청산 요청 (현재 모드)합니다.
지금 실행 중인 거래 봇의 거래만 대상입니다. 거래소 계정 전체를 청산하지 않습니다.

- **모의 모드**: 모의 거래만 청산합니다. 응답은 "모의 거래만 청산했습니다. 실거래 포지션은 비트겟 웹에서 확인하세요."입니다.
- **실전 모드**: 봇이 모르는 포지션(직접 낸 주문, 다른 모드에서 연 거래 등)은 청산되지 않습니다.
  응답의 "봇이 모르는 포지션은 비트겟 웹에서 확인하세요."에 따라 비트겟 웹에서 확인하세요.

3초가 지나면 다시 준비해야 합니다. 일반 작업 중에도 긴급 청산을 요청할 수 있습니다.
접수는 체결 보장이 아닙니다. 포지션이 사라졌는지 직접 확인하세요.
연결 오류나 결과 불명 상태에서는 반복 클릭하지 말고 **비트겟 웹 열기**로 직접 확인·청산하세요.
급하면 비트겟 웹(PC)에서 직접 청산하세요.

### 작업 기록

패널은 설정 변경과 주문 관련 동작(로그인 성공·실패, PIN 설정, 키 저장, 모드 전환, 단계 실행, 거래 봇 시작, 긴급 청산, 폰 접속 켜기)을
`.panel/audit.log`에 한 줄씩 남깁니다. 시각(UTC), 출처(PC `local` / 휴대폰 `tailnet`), 휴대폰 신원, 동작, 결과 코드만 기록하며
키, PIN, 토큰, 요청 내용은 기록하지 않습니다.

## 3. 휴대폰 PIN 설정

PC 바로가기로 연 패널에서 **설정 · 이 PC에서만 표시 → 휴대폰 PIN**을 엽니다.
숫자 6~12자리 PIN을 입력하고 **PIN 저장**을 누릅니다. 휴대폰에서는 PIN을 설정할 수 없습니다.
PIN은 공유하지 마세요. 휴대폰 로그인은 두 가지 기준으로 잠깁니다.

- 같은 Tailscale 신원으로 틀린 횟수가 휴대폰 신원별 5회에 이르면 그 휴대폰 로그인이 15분 잠깁니다.
- 신원과 관계없이 모든 휴대폰의 실패가 전체 합계 5회에 이르면 **모든 휴대폰 로그인**이 15분 잠깁니다.

잠금이 반복되면 대기 시간이 두 배씩 늘어나며 최대 24시간입니다.
PC 접속은 잠기지 않습니다. PC는 PIN이 아닌 바로가기의 토큰으로 엽니다.
세션은 12시간이며 패널 서버를 다시 시작하면 재로그인이 필요합니다.
PIN을 새로 저장하면 로그인된 모든 휴대폰 세션이 끊깁니다. PC 세션은 유지됩니다.

### 휴대폰 분실 시

1. Tailscale 관리 콘솔(Machines 목록)에서 잃어버린 휴대폰 기기를 제거합니다. 그 기기는 더 이상 tailnet에 접속할 수 없습니다.
2. PC 패널에서 **새 PIN**을 저장합니다. 로그인된 휴대폰 세션이 모두 끊깁니다.
3. 또는 패널을 다시 시작합니다. 작업 관리자에서 패널(`pythonw.exe`)을 끝낸 뒤 바로가기를 실행하면 모든 세션이 지워집니다.
4. `.panel/audit.log`에서 휴대폰(`tailnet`) 출처의 최근 동작을 확인하고, 비트겟 웹(PC)에서 포지션과 주문을 확인하세요.

## 4. 휴대폰 연결

1. PC와 폰에 **Tailscale**을 설치하고 **같은 계정**으로 로그인합니다.
2. Tailscale 관리 콘솔의 DNS 설정에서 **HTTPS 인증서 사용**을 켭니다.
3. PC 패널에서 PIN을 먼저 저장합니다.
4. **폰 연결**에서 설치와 로그인이 확인되고 **인터넷 전체 공개: 꺼짐 · 확인됨**인지 확인합니다.
5. **폰 접속 켜기**를 누릅니다. Tailscale Serve로 내 Tailscale 기기에만 연결합니다.
6. 패널에 표시된 `https://…ts.net` 주소를 폰 브라우저에서 엽니다. PC의 토큰 주소는 폰에 복사하지 마세요.
7. PIN으로 로그인합니다.
8. 브라우저 메뉴에서 **홈 화면에 추가**를 선택합니다. iPhone은 Safari의 공유 메뉴를 사용합니다.

**폰 접속 켜기**가 안전 확인에 실패하면 패널은 `tailscale serve reset`을 실행해 공개 설정을 되돌립니다.
이 명령은 이 PC의 **다른 Tailscale Serve 설정도 모두 지웁니다.** 다른 Serve 매핑을 쓰고 있었다면 다시 설정하세요.

패널은 `127.0.0.1:8090`, `localhost:8090`, `이름.tailnet이름.ts.net` 주소로만 응답합니다.
다른 주소 이름으로 열면 "허용하지 않는 접속 주소입니다"(421)가 표시됩니다. 바로가기나 패널에 표시된 테일스케일 주소로 여세요.

**Funnel은 절대 켜지 마세요.** 인터넷 전체 공개 기능은 사용하지 않습니다.
공개 상태가 켜져 있거나 확인 불가이면 폰 접속을 진행하지 말고 Tailscale 설정을 확인하세요.
공유기 포트 포워딩이나 `0.0.0.0` 바인딩도 필요 없습니다. 패널은 `127.0.0.1:8090`에서만 실행됩니다.

**PC가 켜져 있어야 합니다.** 절전·종료·네트워크 끊김 중에는 폰에서 접속할 수 없습니다.
폰에서도 Tailscale 연결이 켜져 있어야 합니다. Tailscale 설치·로그인과 실전 실행은 사용자가 직접 진행합니다.

## 5. 문제 해결

### Docker 오류

- Docker Desktop 오류 창을 확인하고 Docker Desktop이 정상 실행되는지 확인하세요.
- 런처는 Docker에 연결하지 못하고 Docker Desktop 프로세스도 없을 때만
  `%LOCALAPPDATA%\Docker\run\dockerInference` 파일 하나를 지우고 Docker Desktop을 시작합니다.
  다른 Docker 파일이나 폴더를 지우지 않습니다. 실행 중인 Docker Desktop을 강제 종료하지 않습니다.
- 120초 안에 준비되지 않아도 패널은 열리며 도커 상태가 "중지 또는 확인 불가"로 표시됩니다.
  Docker Desktop이 준비되면 패널의 **거래 봇 시작**을 누르거나 바로가기를 다시 실행하세요.
- 거래 봇 시작 실패가 뜨면 `freqtrade/docker-compose.yml`과 개인 설정 파일의 존재·권한을 확인하세요.
  `freqtrade/user_data/config.private.json`의 내용은 출력하거나 공유하지 마세요.

### 패널이 열리지 않음

- `.venv\Scripts\pythonw.exe`가 있는지 확인하세요. 저장소를 옮겼으면 바로가기를 재설치하세요.
- 다른 프로그램이 8090 포트를 쓰면 패널을 시작할 수 없습니다. 해당 프로그램을 확인하세요.
- PowerShell에서 `Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8090/api/ping`으로 응답을 확인할 수 있습니다.
- `Get-NetTCPConnection -LocalPort 8090 -State Listen`의 주소는 `127.0.0.1`만 있어야 합니다.
- **바탕화면 바로가기로 다시 열어 주세요**가 뜨면 바로가기를 다시 실행하세요.
  `.panel\token`의 내용은 표시·복사·공유하지 마세요.
- Edge가 없으면 기본 브라우저가 설정되어 있는지 확인하세요.
- 폰만 접속되지 않으면 PC 전원·절전, 양쪽 Tailscale 로그인, HTTPS 설정, PIN을 확인하세요.
- 청산 요청의 결과가 불명확하면 자동 재시도하지 말고 비트겟 웹에서 체결을 직접 확인하세요.
