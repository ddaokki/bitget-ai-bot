# 구현 로드맵

설계: `docs/superpowers/specs/2026-10-19-bitget-ai-bot-design.md`

설계가 서로 독립적인 하위 시스템 여러 개를 담고 있어서, 계획을 6개로 나눈다. 각 계획은 그 자체로 테스트 가능한 결과물을 낸다. 계획 2부터는 앞 계획의 실제 결과(계정 모드, 스모크 테스트 결과, 백테스트 결과)를 보고 쓴다.

| # | 계획 | 결과물 | 의존 |
|---|---|---|---|
| 1 | 스모크 테스트 최소 경로 (`2026-10-19-plan-1-smoke-test.md`) | 사용자 PC에서 Freqtrade로 최소 실전 주문 → 거래소 손절 확인 → 재시작 확인 → 청산 → 장부 CSV | 없음 |
| 1b | 원클릭 컨트롤 패널 (`2026-10-20-plan-1b-control-panel.md`, 스펙 §10.6) | 스모크 경로를 버튼으로, 바탕화면 원클릭 실행, 폰 접속(Tailscale + PIN), PWA | 1 |
| 2 | 안전 모드 전략 + 백테스트 | 1h 데이터 리샘플 전략, 펀딩 이력 백필, 백테스트 보고서(사용자 진행 결정) | 1 |
| 3 | companion 핵심 | SQLite 장부, rails, 예약 API, 심볼 큐·FLIP 상태 머신, 대조, watchdog, 비상 직접 경로, 텔레그램, 주간 대상 목록 | 1, 2 |
| 4 | 뉴스 수집기 + LLM 판정기 | 수집기, 위험 이벤트, llm-runner 컨테이너, 판정 검증·반영 | 3 |
| 5 | 앱 + 위젯 API | PWA(폰·데스크톱 레이아웃), PIN·Tailscale 신원 인증, 주문 화면, `/api/widget/summary` | 3 (4는 AI 탭에만) |
| 6 | 배포 | 전체 Compose(내부망, Docker secrets), Oracle 또는 PC, Tailscale serve·ACL, 백업, 외부 dead-man | 3~5 |

위젯 보드(`C:\robo-briefing`)는 계약 v1을 `docs/specs/2026-10-19-trading-widget-contract.md`와 `tests/fixtures/trading-summary.json`에 기록했다. 계획 5에서 `/api/widget/summary` 목(mock) 서버가 생기면 URL·포트·실행 방법을 그 세션에 보낸다. 그때 v1 이후 추가된 `positions[].takeProfit`(number|null, §7.5)도 함께 알린다(보드는 모르는 필드를 무시하므로 하위 호환).

계획 1은 사용자 일정(약 24시간 뒤 실전 테스트) 때문에 먼저, 가장 작게 만든다. 계획 1의 `bitgetbot/ftclient.py`, `bitgetbot/bitget_read.py`, `bitgetbot/stopcheck.py`, `bitgetbot/ledger.py`는 계획 3에서 그대로 재사용한다.
