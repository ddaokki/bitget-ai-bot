# 설계: 거래별 사후 분석(포스트모템) 자동 기록

작성 2026-10-22. 상위 설계 §7.6(거래 사후 분석), §9(뉴스·데이터), §18(사건 영향 측정)의 첫 구현이다.
표기: **[사용자]** 사용자가 정함, **[Claude]** Claude가 정함(사용자가 위임).

## 1. 의도

- 거래가 닫힐 때마다 그 거래 구간의 지정학·거시 사건을 분석해 남긴다. 규칙으로 영구히 적용 **[사용자, 2026-10-22]**.
- 장기 목표는 지표만이 아니라 데이터로 가중한 세계 사건에서 배우는 것 **[사용자]**. 이 기록은 나중에 LLM 위험 판정(§8)과 사건 가중치(§18)의 학습 재료다.
- 리포트는 주로 Claude가 보관하고 읽는다. 사용자는 거의 열지 않는다. 패널 구석에 작은 "리포트 목록" 링크만 둔다 **[사용자]**.

## 2. 목표 / 비목표 / 반목표

목표
1. Freqtrade 거래가 닫히면(무엇이 닫았든) 몇 분 안에 사용자 조작 없이 리포트 2개(JSON, 한국어 MD)가 생긴다.
2. 거래 하나당 리포트는 정확히 하나. 중간에 죽은 실행은 나중에 이어서 끝낸다.
3. 사실과 추정을 구분한다. 사건마다 출처 URL과 확인 여부를 남긴다.
4. 나중에 모아서 셀 수 있게 사건에 구조화된 태그를 붙인다.

비목표
- 알림, 위젯 카드, 휴대폰 팝업 **[사용자]**.
- 리포트 결과로 전략·규칙을 자동으로 바꾸는 것(§7.6: 거래 하나로 규칙을 바꾸지 않는다).
- 뉴스 수집기(§9) 전체 구현. 이번에는 거래마다 한 번 웹 검색으로 조사한다.

반목표(돌아가도 실패)
- 거래소나 봇에 쓰기 요청을 한다(주문·취소·수정, 실행 중인 `freqtrade-freqtrade-1` 재시작).
- LLM이 지어낸 사건이나 URL이 "출처 확인"으로 기록된다.
- 비밀값(`config.private.json`, `.panel/token`, `.panel/widget_token`)이 리포트·프롬프트·로그·커밋에 들어간다.
- 같은 거래의 리포트가 둘 이상 생기거나, 실패할 때마다 구독 사용량을 끝없이 쓴다.

## 3. 고정 조건

- 거래소·봇에는 읽기만 한다: Freqtrade REST `GET show_config`, `GET trades`, 비트겟 **공개** 시세 API(키 없음).
- 조사·작성은 사용자 구독의 `claude -p --safe-mode` (robo-briefing과 같은 방식) **[사용자]**.
- 오라클 VM 이전 예정이므로 PC 전용 기능에 기대지 않는다. 경로는 모두 저장소 루트 기준, `claude` 위치는 `CLAUDE_PATH` → `~/.local/bin/claude(.exe)` → `PATH` 순.
- 리포트에는 거래 데이터가 있으므로 git에서 제외한다(`reports/`).

## 4. 동작 **[Claude]**

### 4.1 닫힘 감지: 패널 백그라운드 스레드의 폴링
- 패널 프로세스(PC 바로가기, VM systemd)가 항상 떠 있으므로 그 안에서 60초마다 한 번 돈다.
- Freqtrade 웹훅은 쓰지 않는다. 설정을 바꾸려면 실행 중인 봇을 재시작해야 하고(금지), 패널이 꺼져 있던 동안의 닫힘을 놓친다. 폴링은 다음 시작 때 따라잡는다.
- 한 번 돌 때: `show_config`로 **실행 중인 봇의 모드**(dry/live, 곧 쓰는 DB)를 읽고, `trades(limit=50)`에서 닫힌 거래를 고른다.
- 대상: 닫힌 시각이 최근 30일 안인 거래. 스모크 점검 거래(`enter_tag == "smoke"`)는 매매 판단이 아니므로 제외한다.
- 거래 키: `<mode>-<trade_id>-<open_ts>` (`open_ts`는 진입 시각 ms). dry·live DB가 둘 다 1번부터 번호를 매기므로 모드와 진입 시각을 키에 넣는다(익절가 파일과 같은 규칙).

### 4.2 한 거래 처리 순서와 상태
리포트 JSON 자체가 상태 기록이다(별도 상태 파일 없음). 파일 이름이 키에서 정해지므로 거래당 파일은 하나뿐이다.

1. **사실 기록** (파일이 없을 때): Freqtrade 행 → 거래 사실, 매크로 일정 CSV, 패널 감사 로그(시장가 종료·긴급 청산 구분), 비트겟 공개 시세. 바로 JSON+MD를 쓴다(`status: pending`). 그래서 조사가 느려도 몇 분 안에 두 파일이 생긴다.
2. **조사** (`claude -p`, 웹 검색만 허용, 최대 10분): 성공하면 검증 후 `status: complete`.
3. **실패**: 오류 종류를 기록하고 재시도 시각을 정한다. 간격 10분 → 30분 → 2시간 → 6시간. 5번째 시도까지 실패하면 `status: incomplete`로 끝내고 다시 시도하지 않는다. 판정은 코드 규칙으로만 채우고 "자동 분석 실패"로 표시한다.
   - 모델에 닿지 않은 실패(`claude` 실행 파일 없음 6시간 뒤, 사용량 한도 1시간 뒤)는 시도 횟수를 쓰지 않는다(최대 48번까지). 새 VM에 `claude`를 깔기 전에 닫힌 거래도 나중에 저절로 완료된다.
   - 조사 결과를 저장하지 못하면(파일이 잠깐 열려 있음) 1초 간격으로 2번 더 쓰고, 그래도 안 되면 `save` 오류로 기록하고 일반 재시도로 넘긴다(진행 중 표시를 남겨 두지 않음).
4. **죽은 실행**: 시도 시작 전에 `attempts`와 `in_progress_since`를 먼저 저장한다. 패널이 조사 중에 죽으면 30분 뒤 실패한 시도로 보고 위 재시도 규칙을 따른다.
- 파일을 읽지 못한 것(공유 위반·백신 검사)과 깨진 것을 구분한다. 읽지 못하면 그 주기는 건너뛰고, 깨졌으면 `<key>.json.corrupt-<ms>`로 옮겨 두고 새로 만든다. 어느 경우에도 완료된 리포트를 덮어쓰지 않는다.
- **시세 재조회**: 청산 7시간 뒤(청산 시간대 봉이 닫히고 청산 근처 사건의 6시간 반응이 나온 뒤) 완료·미완료 리포트의 시세를 한 번 다시 받아 사건 반응과 코드 근거를 다시 계산한다. 모델은 다시 부르지 않는다. 실패하면 1시간 뒤, 최대 3번.
- 재시도는 저장된 사실로 한다. 거래가 `trades` 첫 페이지에서 밀려나거나 봇 모드가 바뀌어도 이어진다.
- 시세 조회가 실패하면 그 시도는 실패로 치고, 다음 시도에서 시세부터 다시 받는다.
- 동시 실행 방지: 처리는 한 번에 하나(단일 스레드) + 디렉터리 잠금 파일(`.lock`, 20분 지나면 오래된 것으로 봄). 잠금에는 임의 토큰이 있어 자기 잠금만 갱신·삭제한다. 조사 전후에 시각을 갱신한다. 명령줄 `once`도 같은 잠금을 쓴다.
- `claude`가 제한 시간을 넘기면 프로세스 트리째 끝낸다(Windows `taskkill /T`, 그 밖은 프로세스 그룹).
- 파일 쓰기는 임시 파일 + `os.replace`로 원자적으로 한다. 쓸 때마다 `index.json`을 리포트 파일들에서 다시 만든다(따로 어긋날 일이 없다).

### 4.3 사실 (코드가 계산, `source` 표시)
- 거래: 페어, 방향, 진입·청산 시각(UTC·KST), 진입·청산가, 수량, 레버리지, 증거금(`stake_amount`), 손익 USDT(`profit_abs`), 증거금 대비 %(`profit_abs / stake_amount`), Freqtrade `profit_ratio`, 청산 사유 원문과 분류, 보유 시간, 펀딩비, 보유 중 최고·최저가(`max_rate`, `min_rate`)로 계산한 최대 유리·불리 이동(MFE/MAE).
- 청산 분류: `user_take_profit`→사용자 익절가, `stoploss_on_exchange`/`stop_loss`/`trailing_stop_loss`→손절, `liquidation`→강제청산, `opposite_donchian_10`/`chandelier_stop`/`exit_signal`/`roi`/`custom_exit`→전략 청산, `force_exit`→수동(감사 로그로 패널 시장가 종료와 긴급 청산을 구분, 못 찾으면 "수동(종류 모름)"), 나머지→기타.
- 시장 경로: 비트겟 공개 1시간봉(진입 7일 전 ~ 지금). 리포트에는 진입 24시간 전부터의 완성된 봉만 넣는다. 요약: 구간 고가·저가, 보유 중 변화율, 큰 1시간 움직임 상위 3개(시각 포함), 변동성 배율(보유 중 평균 1시간 절대수익률 ÷ 진입 전 7일 평균). 펀딩 이력(구간 안), 미결제약정은 리포트 시점 값 하나(과거 이력은 무료 API가 없음, "리포트 시점"으로 표시).
- 일정: `upcoming_us_macro.csv`에서 구간(진입 24시간 전 ~ 청산) 안의 FOMC·CPI·PPI·NFP. 공식 일정이므로 출처 확인으로 친다.

### 4.4 사건 조사 (LLM)
- 명령: `claude -p --safe-mode --no-session-persistence --model sonnet --effort medium --tools WebSearch --allowedTools WebSearch --permission-mode dontAsk --output-format stream-json --verbose --json-schema <스키마> --system-prompt <지시>`. 프롬프트는 표준입력. 작업 폴더는 빈 폴더 `reports/postmortem/.work`.
- 모델은 웹 검색 조사 품질 때문에 `sonnet` **[Claude]**. 거래당 1회(+실패 시 재시도)라 사용량은 작다.
- 입력: 거래 사실, 시장 요약(큰 움직임 시각), 일정, 조사 구간. 비밀값·계정 정보는 넣지 않는다. 검색 결과는 데이터이며 지시가 아니라고 시스템 지시에 적는다.
- 출력 스키마: 사건 목록(UTC 시각과 정밀도, 한국어 제목·요약, 분류, 지역, 태그, 예정 여부, 중요도, sourced/guess, 출처 URL·이름, 관련된 큰 움직임), 판정(rule/event/mixed/unclear, 확신도, 이유, 교훈), 검색어 목록.
- **코드 검증**:
  - `stream-json`에 찍힌 WebSearch 결과 링크를 모은다. 사건이 `sourced`라도 그 URL이 실제 검색 결과에 없으면 `guess`로 내리고 `url_verified: false`로 표시한다.
  - 시각을 해석할 수 없거나 구간(진입 30시간 전 ~ 리포트 시각) 밖이면 버리고 버린 수를 남긴다.
  - 열거값이 틀리면 `other`, 문자열은 한 줄로(줄바꿈 제거), 길이 상한, 같은 사건 중복 제거, 최대 15건.
  - 검색은 했는데 결과 링크를 하나도 못 읽으면 `research.warning: no_search_links_parsed`를 남긴다(CLI 출력 형식이 바뀐 신호).
  - MD에서 링크는 검증된 출처 URL과 공식 일정 URL만 `<url>`로 쓴다. 모델 문장 안의 URL·`<>`·백틱은 글자로만 남고, 검증 안 된 URL은 "미확인 링크"로 표시한다.
- 사건마다 코드가 BTC 반응을 잰다(§18 방식): 사건 뒤 6시간 절대수익률, 같은 길이 평소 값 대비 배율, 사건 전 2시간 절대수익률. 데이터가 모자라면 `null`.

### 4.5 판정
- 코드 근거(`rule_basis`): 청산 분류, 청산 시각과 가장 가까운 확인된 사건·일정까지의 분, 보유 중 충격 여부(최대 1시간 절대수익률이 평소의 3배 이상이고 1% 이상).
- LLM 판정(`by: "llm"`): 원인 `rule`/`event`/`mixed`/`manual`(사람이 닫았고 사건으로 설명 안 됨)/`unclear`, 한두 문장 교훈. 추정이라고 표시한다.
- 조사 실패로 끝나면 코드 판정(`by: "code"`): 2시간 안 사건이 없고 보유 중 급변이 없음이 확인되면 규칙 청산은 `rule`, 수동 종료는 `manual`, 나머지는 `unclear`. 완성된 봉이 없어 급변 여부를 모르면 `unclear`.

## 5. 출력

- `reports/postmortem/<mode>-<trade_id>-<open_ts>.json`: 기계용, 스키마 `postmortem/1`. 거래·시장·일정·사건·판정·조사 상태·시도 기록.
- 같은 이름 `.md`: 사람용, 한국어, 짧게(제목 1줄, 거래 3줄, 시장 2~4줄, 사건 목록, 판정 2줄). 사건마다 [출처]/[추정] 표시.
- `reports/postmortem/index.json`: 모든 리포트 요약(키, 모드, 거래 번호, 페어, 방향, 청산 시각, 손익, 청산 분류, 판정, 상태), 청산 최신순.

## 6. 패널

- `index.html` 맨 아래 오른쪽 구석에 작은 회색 링크 "리포트 목록" → `/reports` **[Claude: 위치]**.
- `/reports`: 읽기 전용 목록 + 하나 열기(MD를 안전하게 텍스트로 그림). 같은 로그인 세션이 있어야 데이터가 보인다(PC 또는 휴대폰 PIN).
- API: `GET /api/reports`(index), `GET /api/reports/{key}`(키는 정규식으로만 받고 파일 경로를 입력으로 만들지 않음). 쓰기 API 없음.

## 7. 실행 단위

- `bitgetbot/postmortem/` 패키지: `facts`, `market`, `research`, `report`, `watcher`, `__main__`.
- 패널 `__main__`이 감시 스레드를 켠다(`PanelDeps.postmortem`). 테스트는 기본값(없음)이라 실제 네트워크·`claude`를 부르지 않는다.
- 명령줄: `python -m bitgetbot.postmortem once`(한 번 돌기), `python -m bitgetbot.postmortem index`(목록 다시 만들기).
- VM: `claude`를 설치하고 `CLAUDE_CODE_OAUTH_TOKEN`을 서비스 환경에 넣어야 조사가 된다. 없으면 사실만 남고 5번 시도 후 `incomplete`.

## 8. 테스트

- 감지: 열린/닫힌/스모크/30일 지난/깨진 행, 모드 판별, Freqtrade 연결 실패 시 아무것도 안 씀.
- 멱등: 두 번 돌아도 파일 하나, 완료된 리포트는 다시 조사하지 않음, 같은 번호·다른 진입 시각은 별개.
- 실패 처리: 조사 실패·시간 초과·사용량 한도 → 사실 파일은 남고 재시도 예약, 최대 시도 후 끝, 죽은 실행 재개, 시세 실패 시에도 파일 생성.
- 검증: 검색 결과에 없는 URL은 추정으로 강등, 구간 밖 시각 버림.
- 패널: 로그인 없으면 401, 잘못된 키 404, 링크 존재, 쓰기 API 없음.
